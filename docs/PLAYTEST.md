# Наблюдаемый тест — как провести

Этап 6 плана прототипа. Цель — качественные наблюдения на 5–10 сессиях, а не статистика.

## Подготовка

1. Запустить игру так, чтобы её было видно с телефона в той же сети:
   ```bash
   npm run dev -- --host
   ```
   На телефоне открыть адрес `Network` из консоли.
2. Для каждого игрока — чистое сохранение. На компьютере: кнопка DBG → закрыть, затем в консоли браузера `localStorage.clear()` и перезагрузка. На телефоне — приватная вкладка.
3. Реклама на localhost не показывается; для проверки рекламных сценариев — `?fakeads=1` в адресе.
4. Энергия включена по умолчанию. Для исследовательского теста без ожиданий: DBG → «Энергия без лимита».

## Во время сессии

Не подсказывать, пока игрок не застрял больше минуты. Записывать:

- где игрок остановился и что пытался сделать;
- понял ли разницу между заказами и ремонтом;
- замечает ли изменения в магазине;
- пользуется ли складом, продажей и окном «Где получить?».

## После сессии

1. DBG → «Скачать журнал теста». Файл содержит события и итоговое состояние, без персональных данных.
2. Задать вопросы из [плана, раздел 4](PROTOTYPE_PLAN.md#4-вопросы-после-сессии).

## Что в журнале

| Поле / событие | Значение |
| --- | --- |
| `activeMs` | Время активной игры (без паузы и скрытой вкладки) |
| `spawnsTotal`, `spawnsByGenerator` | Выдачи всего и по генераторам |
| `refusals` | Отказы выдачи: `board_full`, `no_energy` |
| `sales`, `undos` | Продажи и отмены продаж |
| `tutorial_step`, `tutorial_completed` | Пройденные шаги обучения |
| `first_merge` | Первое объединение |
| `order_delivered`, `project_completed` | Сдача цели: `spawns` — выдачи с прошлой цели, `active_sec` — время с начала |
| `chapter_completed` | Завершение R08 |
| `session_start` | Запуск; `returning` — продолжение сохранения |

Вехи (`session_start`, шаги обучения, первое объединение, сдачи, отказы, конец главы) также уходят в аналитику площадки через `bridge.analytics.send`. Журнал хранится вместе с сохранением, последние 300 событий.
